These are **atomic single-key operations**, not a read-modify-write of the whole blob at the library
layer. `setCustomProperty` and `removeCustomProperty` are dedicated repository primitives, so a
concurrent write to a different key doesn't clobber yours.

<Aside type="caution" title="Atomic, with one asterisk">
  The guarantee is only as strong as the backend. `InMemoryMediaRepository` and SQLite serialize it
  fully. On Postgres or MySQL under the default read-committed isolation, two concurrent merges on
  the _same record_ can still lose one — see [known
  limitations](/production/limitations/#prisma-json-column-merges-arent-lock-safe).
</Aside>

If you need to replace the whole object, `withCustomProperties()` at upload time sets it wholesale;
after that, go key by key.

## Querying by property

An object filter requires **every** key to deep-equal the stored value. A function filter is an
arbitrary predicate over the full `MediaRecord`, so you can reach `size`, `mimeType`, `createdAt`, or
anything else.

Both filter in memory after fetching the model's media — fine for a model's own collections, which are
bounded by design. This is not a substitute for a database query across all media; for that, hit your
own table.

## Copying and moving between owners

Reassigning a draft's uploads to the published post, or transferring an asset between accounts:

<Code code={snippet(source, 'copy-move')} lang="ts" title="images.ts" />

Both re-run the **full add pipeline** against the target. That has consequences worth being explicit
about:

- The **target** collection's validation applies. Copying a GIF into a PNG-only collection fails.
- The **target** collection's rules apply. Copy twice into a `singleFile()` collection and you end up
  with one record, not two.
- The target's disk configuration applies, so media can move between disks.
- Derived files are **regenerated**, never byte-copied from the source's conversions.
- The copy gets a new `id` and `uuid`; custom properties and manipulations carry over.

`moveMedia` is copy-then-delete-source. If the copy fails, the source is left completely untouched —
there's no window where both are gone.

Both emit typed events: `media:copied` with `{ media, copy }`, and `media:moved` with
`{ media, moved }`.
